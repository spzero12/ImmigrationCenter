# Roadmap

## Этап 0 — Фундамент (готово)

- [x] Базовая структура проекта (PHP + jQuery).
- [x] Общие header/footer, подключение стилей и скриптов.

## Этап 1 — Данные и авторизация (готово)

- [x] Подключение MySQL, схема БД: сотрудники, роли пользователей.
- [x] Аутентификация и ролевая модель (администратор, HR, юрист,
      руководитель).
- [x] CRUD карточки иностранного сотрудника (личные данные, гражданство,
      должность, подразделение).

## Этап 2 — Миграционный учёт (готово, кроме напоминаний)

- [x] Учёт разрешительных документов сотрудника (паспорт, виза, патент,
      разрешение на работу, регистрация) со сроками действия.
- [x] Список/дашборд с фильтрацией по сроку истечения (просрочено / скоро
      истекает / в порядке / без срока) и счётчиками на `documents.php`.
- [ ] Напоминания о приближающихся дедлайнах (в интерфейсе, позже — email) —
      статусы уже вычисляются, самих уведомлений (push/email) пока нет,
      перенесено в Этап 5.

## Этап 3 — Документы (готово, кроме PDF)

- [x] Шаблоны миграционной карты и сопутствующих документов — реального
      .docx от заказчика нет, поэтому собран свой рабочий шаблон
      [templates/visa.docx](../../templates/visa.docx) (сгенерирован
      PHPWord, все 18 плейсхолдеров из спецификации). Заменить, когда
      появится официальный.
- [x] Автозаполнение шаблонов данными сотрудника — `document_generate.php`
      и логика единого источника/`field_overrides`
      ([спецификация](../specs/2026-08-20-document-generation/spec.md))
      проверены локально сквозным сценарием (PHP 8.4 + MariaDB 11.8.8 на
      этой машине): сгенерированный .docx на `templates/visa.docx`
      содержит верно подставленные данные (включая переопределённую
      фамилию и паспортные данные из единой карточки), плейсхолдеров
      `${...}` в выводе не осталось.
- [ ] Экспорт документов в PDF — сознательно вынесено из этой версии,
      `.docx` пока достаточно (см. спецификацию, раздел «Вне рамок»);
      вернуться к этому пункту отдельно, если понадобится.
- [x] Загрузка и хранение сканов документов сотрудника —
      `document_scan_upload.php`/`document_scan.php` проверены локально
      (загрузка JPG, авторизованная отдача, редирект на логин без сессии).
      Защита `uploads/` через `.htaccess` — только для Apache (у хостинга),
      локальный сервер PHP её не применяет и не проверялась на ней.

## Этап 4 — Отчётность и аудит (готово)

- [x] Сводные отчёты по иностранным сотрудникам (для руководства) —
      `reports.php`: сводка по сотрудникам (гражданство/подразделение,
      кол-во документов), статусы документов на выбранную дату, история
      добавлений за период. Доступно всем ролям (руководителю в том числе).
- [x] Экспорт отчётов в Excel — `report_export.php`
      (`phpoffice/phpspreadsheet` 1.30.6), сводка по сотрудникам в `.xlsx`.
- [x] Журнал аудита: кто и когда менял данные/документы сотрудника —
      `audit_log.php` (роль `admin`), таблица `audit_log`, логирование
      create/update/delete для сотрудников и документов
      ([спецификация](../specs/2026-08-20-reporting-audit/spec.md)). Без
      диффа старых/новых значений полей — сознательно упрощено.

Проверено сквозным сценарием локально (PHP 8.4 + MariaDB 11.8.8): записи
аудита корректны даже после удаления сущности, ролевые ограничения
работают, `.xlsx` перепроверен обратным чтением.

## Этап 5 — Улучшения (по мере необходимости)

- [ ] Email/SMS-уведомления о сроках.
- [ ] Массовый импорт сотрудников (CSV/Excel).
- [ ] Переход на полноценный фреймворк (Laravel/Symfony), если сложность

## Отслеживание прогресса

Список выше отражает текущий фактический статус. Каждый выполненный пункт
должен быть отмечен `[x]` вместе с соответствующим коммитом/изменением
кода — roadmap не поддерживается вручную "на будущее", а соответствует
реальному состоянию проекта.
