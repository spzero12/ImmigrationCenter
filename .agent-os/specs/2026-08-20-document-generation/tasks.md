## Блокер (остаётся открытым)

- [ ] **Установить Composer-зависимости по-прежнему негде.** Код написан в
      расчёте на `vendor/autoload.php`, но `composer install` не выполнялся
      — ни в этой среде, ни на хостинге (только FTP) его выполнить нельзя.
      `document_generate.php` при отсутствии `vendor/autoload.php` отдаёт
      понятную ошибку вместо фатального краша, но реально сгенерировать
      документ до этого шага нельзя. Нужно на любой машине с PHP + Composer
      выполнить `composer require phpoffice/phpword` (зависимость уже
      описана в `composer.json`), закоммитить `composer.lock`, а
      получившийся `vendor/` — скопировать в `deploy/` при выкладке
      (`deploy/` целиком игнорируется и пересобирается вручную — не забыть
      добавить `vendor/` в список копируемых папок).
- [ ] **Нет реального .docx-шаблона.** `templates/` пуста. Как появится —
      сверить его плейсхолдеры с таблицей в spec.md (или поправить маппинг
      под то, что реально в файле) и положить в `templates/` под именем
      типа документа (`passport.docx`, `visa.docx` и т.д.).

Без этих двух пунктов сгенерировать реальный .docx нельзя, но весь
остальной код (миграции, разделение ФИО, сканы, редактируемые общие
данные) написан и не зависит от них.

## Реализация

- [x] `db/migrations/003_employee_name_parts.sql` — `last_name`/`first_name`
      (обяз.)/`middle_name` (необяз.) в `employees` + бэкофилл из текущего
      `full_name` (наивное разбиение по пробелам — для нестандартных ФИО
      возможна ручная правка после применения миграции).
- [x] `employee_form.php` — три поля вместо одного «ФИО»; `full_name`
      пересобирается при сохранении, существующий код, читающий
      `full_name` (`employees.php`, `api/employees.php`,
      `api/documents.php`), не тронут.
- [x] `db/migrations/004_document_scans_and_overrides.sql` —
      `scan_stored_name`, `scan_original_name`, `scan_mime_type`,
      `scan_size`, `field_overrides` (`JSON NULL`) в `employee_documents`.
- [x] `uploads/documents/` + `uploads/.htaccess` (`Deny from all` —
      полный запрет прямого HTTP-доступа, не только выполнения скриптов),
      `/uploads/documents/*` в `.gitignore` (кроме `.gitkeep`).
- [x] `document_scan_upload.php` — приём файла, валидация (реальный MIME
      через `finfo`, whitelist jpg/png/pdf, лимит 10 МБ), сохранение под
      случайным именем, запись в БД, удаление старого файла при замене.
- [x] `document_scan.php` — отдача файла скана залогиненному пользователю
      (`Content-Disposition: inline`, `Content-Type` по сохранённому MIME).
- [x] `includes/documents.php`: `getCanonicalPassport()`,
      `documentCommonFieldDefaults()` (единый источник как есть),
      `documentEffectiveCommonFields()` (источник + overrides),
      `documentBuildOverrides()` (диф отправленных значений от источника),
      `documentTemplatePlaceholders()` (полный набор для генерации).
- [x] `document_form.php` — редактируемые поля общих данных (предзаполнены
      эффективными значениями); при сохранении сравниваются с единым
      источником на момент сохранения, в `field_overrides` попадает только
      реально отличающееся.
- [x] `document_generate.php` — `TemplateProcessor` из PHPWord (при наличии
      `vendor/` и шаблона в `templates/`), временный файл вместо
      `php://output` (`ZipArchive` требует реальный путь), удаляется сразу
      после отдачи.
- [x] `document_form.php` / `employee_form.php` / `js/documents.js` — кнопка
      «Скачать .docx» и блок загрузки/замены скана.

## Проверка (не выполнена — нужен `vendor/`, реальный шаблон и работающий PHP)

- [ ] Загрузить скан в JPG/PNG/PDF — сохраняется, скачивается только под
      логином, файл с левым MIME/расширением отклоняется.
- [ ] Сгенерировать .docx на реальном шаблоне — плейсхолдеры подставились
      верно, кириллица не побилась.
- [ ] Изменить фамилию в конкретном документе (не трогая карточку
      сотрудника) → сохраняется как `field_overrides`, при генерации
      используется именно она; в других документах того же сотрудника,
      где фамилию не трогали, по-прежнему видна фамилия из карточки.
- [ ] Изменить фамилию в карточке сотрудника → во всех документах без
      override значение обновилось само; в документе с override — нет.
- [ ] Убедиться, что `uploads/documents/*` недоступны напрямую по URL
      (должен вернуться 403 от Apache, а не файл).
- [ ] Проверить бэкофилл ФИО на реальных данных сотрудников (если они уже
      есть в БД) — простое разбиение по пробелам может ошибиться на
      нестандартных именах.

После ручной проверки отметить пункты выше и обновить чек-бокс Этапа 3 в
[roadmap.md](../../product/roadmap.md).
