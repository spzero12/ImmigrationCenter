# Спецификация: Миграционный учёт (документы и сроки)

Соответствует Этапу 2 [roadmap](../../product/roadmap.md).

## Цель

Хранить у каждого иностранного сотрудника набор разрешительных документов со
сроками действия и показывать HR/юристу, какие документы просрочены или скоро
истекают — без ручных таблиц.

## Типы документов (первая версия)

- `passport` — паспорт
- `visa` — виза
- `work_patent` — патент на работу
- `work_permit` — разрешение на работу
- `registration` — регистрация по месту пребывания

Список типов зафиксирован в ENUM на уровне БД. Добавление нового типа —
миграция БД + правка констант в коде.

## Данные документа

- сотрудник (employee_id)
- тип документа (из списка выше)
- номер, серия (опционально — не у всех типов есть серия)
- дата выдачи
- дата окончания срока действия
- кем выдан / орган выдачи (опционально)
- примечания
- кто и когда создал/изменил запись

## Статус документа (вычисляемый, не хранится)

Считается на лету от `expire_date` относительно текущей даты:

- **Просрочен** — `expire_date < сегодня`
- **Скоро истекает** — `expire_date` в пределах ближайших 30 дней
- **В порядке** — иначе
- **Без срока** — `expire_date` не заполнена (например, для паспорта не всегда
  критично отслеживать)

Порог в 30 дней задаётся константой, чтобы его было легко поменять.

## Функциональные требования

1. На карточке сотрудника — список его документов с статусами.
2. Отдельная страница «Документы» — сводный список документов всех
   сотрудников с фильтром по статусу (просрочен / скоро истекает / все) и
   поиском по сотруднику.
3. Добавление / редактирование / удаление документа сотрудника.
4. Права: удаление документа — только `admin` и `hr` (как и для сотрудников).
5. Дашборд/счётчики: сколько документов просрочено, сколько истекает в
   ближайшие 30 дней (для главной страницы или верхней части списка).

## Вне рамок этой фичи (следующие этапы roadmap)

- Email/SMS-уведомления о сроках (Этап 5).
- Генерация PDF/DOCX документов по шаблонам (Этап 3).
- Загрузка сканов документов как файлов (Этап 3).
- Журнал аудита изменений (Этап 4).

## Изменения в данных

Новая таблица `employee_documents`, связана с `employees` через `employee_id`
(`ON DELETE CASCADE` — при удалении сотрудника его документы удаляются тоже).
См. [db/migrations/002_employee_documents.sql](../../../db/migrations/002_employee_documents.sql).

## Затрагиваемые файлы (код-заглушки на этом шаге)

- `db/migrations/002_employee_documents.sql` — схема таблицы (реализовано).
- `documents.php` — страница сводного списка документов (заглушка).
- `document_form.php` — форма добавления/редактирования документа (заглушка).
- `api/documents.php` — JSON API для списка/создания/обновления/удаления
  (заглушка, методы возвращают 501 Not Implemented).
- `js/documents.js` — клиентская логика AJAX (заглушка с TODO).

Полная реализация — отдельным шагом, по чек-листу в
[tasks.md](tasks.md).
