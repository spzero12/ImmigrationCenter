# Задачи: Миграционный учёт (документы и сроки)

## Подготовка (этот шаг)

- [x] Спецификация ([spec.md](spec.md)).
- [x] Миграция БД `employee_documents`.
- [x] Заглушки страниц/API/JS.

## Реализация

- [ ] `includes/documents.php` (или хелпер в `includes/db.php`) — функция
      вычисления статуса документа по `expire_date` (просрочен / скоро
      истекает / в порядке / без срока).
- [ ] `api/documents.php`:
  - [ ] `GET` — список документов (с фильтром `employee_id`, `status`).
  - [ ] `POST` — создание документа.
  - [ ] `PUT`/`POST` с `id` — обновление документа.
  - [ ] `DELETE` — удаление (роли `admin`, `hr`).
- [ ] `document_form.php` — сохранение формы через `api/documents.php` или
      напрямую (по аналогии с `employee_form.php`).
- [ ] `documents.php` — сводная таблица со статусами, фильтром и поиском.
- [ ] `js/documents.js` — загрузка/рендер/удаление документов через AJAX.
- [ ] Блок документов и статусов на `employee_form.php` (карточка
      сотрудника) при редактировании существующего сотрудника.
- [ ] Пункт «Документы» в навигации (`includes/header.php`).
- [ ] Счётчики просроченных/истекающих документов (например, на
      `employees.php` или отдельным блоком).

## Проверка

- [ ] Ручное тестирование: создать документ с прошедшей датой → статус
      «просрочен»; с датой через 10 дней → «скоро истекает»; через 100 дней →
      «в порядке».
- [ ] Удаление сотрудника каскадно удаляет его документы.
- [ ] Роль `manager`/`lawyer` не может удалить документ (только просмотр/по
      необходимости — уточнить при реализации).
