# Задачи: Миграционный учёт (документы и сроки)

## Подготовка (этот шаг)

- [x] Спецификация ([spec.md](spec.md)).
- [x] Миграция БД `employee_documents`.
- [x] Заглушки страниц/API/JS.

## Реализация

- [x] `includes/documents.php` — `documentStatus()` вычисляет статус по
      `expire_date` (просрочен / скоро истекает (30 дней) / в порядке / без
      срока) + `DOCUMENT_TYPE_LABELS`.
- [x] `api/documents.php`:
  - [x] `GET` — список документов (фильтр `employee_id`, поиск `q` по
        сотруднику; фильтр по `status` сделан на клиенте в `documents.js`,
        так как статус вычисляется на лету и уже есть в каждой строке).
  - [x] `DELETE` — удаление (роли `admin`, `hr`).
  - Создание/обновление сделаны **не** через API, а напрямую в
    `document_form.php` — по тому же паттерну, что и `employee_form.php`
    (там тоже нет `POST`/`PUT` в `api/employees.php`). `POST`/`PUT` к
    `api/documents.php` отдают 405.
- [x] `document_form.php` — принимает `employee_id` (обязателен) и `id`
      (для редактирования), сохраняет напрямую в БД, редиректит на карточку
      сотрудника.
- [x] `documents.php` — сводная таблица, поиск по сотруднику, фильтр по
      статусу, счётчики просроченных/истекающих.
- [x] `js/documents.js` — загрузка/рендер/фильтр/удаление через AJAX.
- [x] Блок документов и статусов на `employee_form.php` при редактировании
      существующего сотрудника (+ добавление/удаление документа).
- [x] Пункт «Документы» в навигации — уже был добавлен фичей design-system.
- [x] Счётчики просроченных/истекающих документов — отдельным блоком на
      `documents.php`.

## Проверка (требует ручной проверки — PHP не установлен в этой среде)

- [ ] Ручное тестирование: создать документ с прошедшей датой → статус
      «просрочен»; с датой через 10 дней → «скоро истекает»; через 100 дней →
      «в порядке»; без даты → «без срока».
- [ ] Удаление сотрудника каскадно удаляет его документы (гарантируется
      `ON DELETE CASCADE` в миграции — стоит проверить на реальных данных).
- [ ] Роль `manager`/`lawyer` не видит кнопку «Удалить» ни у сотрудника, ни
      у документа (проверено в коде через `in_array(..., ['admin','hr'])`,
      но не проверено вживую).

После ручной проверки отметить пункты выше.
