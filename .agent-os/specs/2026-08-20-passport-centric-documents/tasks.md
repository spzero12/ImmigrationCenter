# Задачи: Паспорт как единая карточка + поле «Организация»

## Подготовка

- [x] Спецификация ([spec.md](spec.md)) — решение по структуре
      (`passport_document_id` на документе, не слияние полей в паспорт),
      по смыслу поля «Организация» (юрлицо, отдельно от «Подразделения»).

## Реализация

- [x] `db/migrations/006_passport_link_and_organization.sql`:
  - [x] `employees.organization VARCHAR(255) NULL`.
  - [x] `employee_documents.passport_document_id INT UNSIGNED NULL` +
        `FOREIGN KEY ... ON DELETE SET NULL`. Без `CHECK` — MariaDB 12.3.2
        отказывается добавлять self-referencing `FOREIGN KEY` на колонку,
        участвующую в `CHECK` (см. комментарий в файле миграции); правило
        «паспорт не ссылается сам на себя» гарантируется в PHP.
  - [x] Бэкофилл: непаспортные документы → паспорт с максимальной
        `issue_date` того же сотрудника.
- [x] `includes/documents.php`:
  - [x] `DOCUMENT_COMMON_FIELDS` + `'organization'`.
  - [x] `documentCommonFieldDefaults()` — `organization` из `$employee`.
  - [x] `getLinkedPassport()` + `getEmployeePassports()` — новые функции.
  - [x] `documentTemplatePlaceholders()` — `${organization}`; особый
        случай для типа `passport` (паспортные плейсхолдеры из своих же
        полей).
- [x] `document_form.php`:
  - [x] Выпадающий список «Паспорт» для непаспортных типов (обязателен,
        скрывается через JS при выборе типа "Паспорт").
  - [x] Блокировка создания непаспортных документов, если у сотрудника
        нет ни одной записи паспорта — и на UI (select задизейблен,
        показано сообщение), и на сервере (отдельная проверка при POST,
        не полагается только на клиент).
  - [x] Поле «Организация» в блоке общих данных.
  - [x] Сохранение `passport_document_id` при create/update.
- [x] `employee_form.php`:
  - [x] Поле «Организация» в форме.
  - [x] Колонка «Паспорт» в списке документов сотрудника (номер
        привязанного паспорта или «не привязан» красным).
- [x] `document_generate.php` — паспорт через `getLinkedPassport()`.
- [x] Таблица плейсхолдеров в spec.md фичи document-generation обновлена
      (`${organization}`, пересмотрено описание источника `${passport_*}`).
      `templates/visa.docx` пересобран с новым полем (19 плейсхолдеров).
- [x] `deploy/` обновлён (по факту коммита — команда пересборки та же,
      что и раньше).

## Проверка

Выполнено локально сквозным сценарием (PHP 8.4 + MariaDB 12.3.2, служба
Windows, `root`/`spider`):

- [x] Создан паспорт (AB111222) → создана виза, привязанная к нему →
      сгенерирован .docx → все 19 плейсхолдеров подставились, включая
      `${organization}` ("ООО Ромашка") и паспортные поля из привязанной
      записи, `${...}` в выводе не осталось.
- [x] Выдан сотруднику **второй** (более новый) паспорт (CD999888) →
      старая виза осталась привязана к старому паспорту id — при
      повторной генерации той же визы в документе по-прежнему AB111222,
      а не CD999888. Новый документ, создаваемый после этого, по
      умолчанию предлагает уже новый паспорт (CD999888) в выпадающем
      списке.
- [x] Форма создания документа для сотрудника без паспорта: тип
      ограничен только "Паспорт", показано пояснение. Прямой POST
      `type=visa` в обход UI отклонён сервером ("Сначала добавьте
      паспорт сотруднику").
- [x] Удалён паспорт, к которому была привязана виза → виза не
      удалилась, `passport_document_id` стал `NULL` (не ошибка 500);
      форма редактирования и генерация .docx для такого документа
      продолжают открываться (200), список документов сотрудника
      показывает «не привязан».
- [x] Поле «Организация» сохраняется в карточке сотрудника и
      предзаполняет форму документа.
- [x] Аудит по-прежнему логирует create/update при работе через
      `document_form.php`/`employee_form.php` (изменения в этих файлах
      не задели существующий вызов `logAudit()`).
