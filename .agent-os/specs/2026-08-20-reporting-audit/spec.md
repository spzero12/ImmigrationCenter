# Спецификация: Отчётность и аудит (Этап 4)

Соответствует Этапу 4 [roadmap](../../product/roadmap.md).

## Приоритет

По ответам на вопросы: **журнал аудита — главное** в этой фиче. Отчётность
и экспорт в Excel тоже входят в первую версию (содержание определено ниже),
но аудит — то, без чего остальное не так критично.

## 1. Журнал аудита

### Что фиксируется

Создание / изменение / удаление сотрудников и документов. **Без** диффа
старых/новых значений полей — только факт: кто, когда, что и с каким
действием (по ответам на вопросы — минимальный вариант, без входа/выхода
из системы и без полного diff).

### Модель данных

Новая таблица `audit_log`:

| Поле | Тип | Комментарий |
|---|---|---|
| `id` | INT UNSIGNED AUTO_INCREMENT | |
| `user_id` | INT UNSIGNED NULL | `ON DELETE SET NULL` — запись остаётся, даже если пользователя удалят |
| `action` | ENUM('create','update','delete') | |
| `entity_type` | ENUM('employee','employee_document') | |
| `entity_id` | INT UNSIGNED | ID записи (может уже не существовать после удаления) |
| `entity_label` | VARCHAR(255) | Человекочитаемый снимок на момент действия (см. ниже) — так запись остаётся понятной и после удаления самой сущности |
| `created_at` | TIMESTAMP DEFAULT CURRENT_TIMESTAMP | |

`entity_label`:
- для `employee` — `full_name` на момент действия;
- для `employee_document` — `"{человекочитаемый тип} {number} — {full_name сотрудника}"`,
  например `"Виза V-99887766 — Петров Иван Иванович"`.

### Где логируется

Один хелпер `logAudit()` в [includes/audit.php](../../../includes/audit.php),
вызывается точечно в местах, где уже происходит запись в БД:

- `employee_form.php` — после INSERT (create) и после UPDATE (update).
- `api/employees.php` — в ветке DELETE, **до** самого удаления (иначе
  негде взять `full_name` для `entity_label`).
- `document_form.php` — после INSERT и после UPDATE.
- `api/documents.php` — в ветке DELETE, до удаления (та же причина; заодно
  нужен JOIN на `employees` за именем сотрудника).

### Страница просмотра

`audit_log.php` — доступ только роли `admin` (аудит — не то, что должны
листать все; при необходимости расширить список ролей позже). Таблица:
дата/время, пользователь, действие, тип сущности, `entity_label`,
ссылка на сущность (если ещё существует). Фильтры: тип сущности,
действие. Без сложной пагинации — последние 200 записей достаточно для
первой версии (при необходимости расширить позже).

## 2. Сводная отчётность (`reports.php`)

Три блока по ответам на вопросы:

1. **Сводка по сотрудникам** — всего сотрудников, разбивка по
   гражданству/подразделению, сколько документов у каждого.
2. **Статусы документов на дату** — то же, что счётчики на
   `documents.php` (просрочено / скоро истекает / в порядке / без срока),
   но с возможностью выбрать **любую** дату, не только сегодня.
   `documentStatus()` в [includes/documents.php](../../../includes/documents.php)
   получает необязательный второй параметр `$referenceDate = null`
   (по умолчанию — сегодня); отчёт просто пересчитывает статус относительно
   выбранной даты — это корректно, потому что `expire_date` не меняется
   задним числом, реальных исторических данных восстанавливать не нужно.
3. **История за период** — сколько сотрудников и документов добавлено за
   выбранный диапазон дат (`employees.created_at` /
   `employee_documents.created_at`), плюс сам список.

Роли: отчёты — только для чтения, доступны всем аутентифицированным
ролям (включая `manager`, для которого это единственный сценарий
использования портала по mission.md).

## 3. Экспорт в Excel

**Библиотека**: `phpoffice/phpspreadsheet`, версия `^1.29` (не `^5`) —
чтобы не требовать PHP 8.2+, раз реальная версия PHP на хостинге не
подтверждена (текущий `composer.json` держит минимум `>=8.0`).

`report_export.php` — экспортирует блок «Сводка по сотрудникам» (тот же
набор данных, что на экране: ФИО, гражданство, подразделение, количество
документов, статус ближайшего по сроку документа) в `.xlsx`, отдаёт как
скачивание тем же паттерном, что `document_generate.php` (временный файл
через `tempnam()`, `readfile()`, `unlink()` сразу после отдачи — ничего не
остаётся на диске).

## Вне рамок этой фичи

- Diff старых/новых значений полей в аудите (сознательно упрощено).
- Логирование входа/выхода из системы.
- Экспорт в Excel истории за период или журнала аудита (только сводка по
  сотрудникам, на первую версию).
- Сложная пагинация/поиск в журнале аудита.
