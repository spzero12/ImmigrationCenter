# Деплой на хостинг (FTP + phpMyAdmin)

Хостинг: только FTP и phpMyAdmin, без SSH/Composer. БД (из `config/config.php`):
хост `p902341.mysql.ihc.ru`, база `p902341_migra`. Папка `deploy/` в проекте —
**устаревшая** (gitignored, старые файлы), её не заливать.

## 0. Перед началом

- [ ] Ветка собрана и проверена локально, `git status` чистый (кроме
      образцов .docx/.jpg в корне — они на сервер не нужны).
- [ ] В панели хостинга: версия PHP **8.0+** (лучше 8.2/8.3) и включены
      расширения `zip`, `gd`, `mbstring`, `xml`, `dom`, `xmlwriter`,
      `simplexml`, `fileinfo`, `iconv` (нужны PhpWord/PhpSpreadsheet —
      без `zip` не формируются .docx).
- [ ] Есть доступ: FTP-логин/пароль, phpMyAdmin.
- [ ] Определено, **новая** это установка или **обновление** (см. шаг 2).

## 1. Собрать пакет

```powershell
powershell -ExecutionPolicy Bypass -File scripts\build_deploy.ps1
```

Появится `_deploy_build\` (~15 МБ, ~1500 файлов): PHP-страницы, `api/`, `css/`,
`js/`, `includes/`, `config/`, `vendor/`, `templates/processes/`, пустые
`uploads/*` и `.htaccess` (запрет PHP в `uploads/`, закрытие `includes/`,
`config/`, `templates/` от прямого доступа). Не попадают: `deploy/`, `.git`,
`.agent-os`, `_tmp_preview`, образцы Word/JPG, `templates/samples`, `db/`,
`password.txt`, корневой `config.php`.

Проверьте `_deploy_build\config\config.php` — в нём должны быть боевые данные БД
(host/name/user/pass). Если нет — поправьте **только в копии**.

## 2. База данных (phpMyAdmin)

Откройте phpMyAdmin → выберите базу `p902341_migra` (слева).

### 2а. Первая установка / пересоздание с нуля

⚠️ `production_rebuild.sql` **удаляет** все таблицы проекта и создаёт пустыми.

1. Если в базе есть данные — вкладка **Экспорт** → «Быстрый» → SQL → сохранить
   бэкап локально.
2. Вкладка **Импорт** → файл `db/production_rebuild.sql` → кодировка `utf-8` →
   «Вперёд». Файл уже содержит все миграции до 018, регион «Москва» и админа.
3. Проверка: в списке 10 таблиц — `users`, `organizations`, `departments`,
   `regions`, `organization_signers`, `employees`, `employee_documents`,
   `employee_processes`, `process_documents`, `audit_log`; в `users` одна
   строка `admin`.

### 2б. Обновление существующей БД с данными

Не запускайте rebuild. Узнайте, какие миграции уже применены (сверьте
структуру таблиц: например, есть ли у `employees` колонки `last_name_lat`
= 016, таблица `organization_signers` = 015, `letterhead_stored_name` у
`organizations` = 014, `employee_processes` = 013). Затем **Импорт** по
одному недостающим `db/migrations/0NN_*.sql` строго по порядку номеров.
Перед этим — обязательный бэкап (Экспорт).

## 3. Загрузка файлов по FTP

1. Подключитесь (FileZilla/WinSCP; протокол FTP/FTPS, режим **Binary**).
2. Перейдите в корень сайта (обычно `public_html/` или `www/<домен>/`).
   Если сайт живёт в подпапке — заливайте в неё.
3. Загрузите **содержимое** `_deploy_build\` (не саму папку) в корень сайта.
   `vendor/` — самая долгая часть (~1400 файлов): включите несколько
   параллельных соединений (4–5) или залейте `vendor.zip`, если хостинг
   умеет распаковывать архивы.
4. Для обновления: перезаписывайте файлы, но **не удаляйте и не
   перезаписывайте `uploads/`** на сервере — там реальные сканы, фото и
   бланки. Файлы в `uploads/` из пакета не заливайте при обновлении
   (в пакете они пустые, но `.htaccess` из `uploads/` залить нужно один раз).
5. Права: каталоги `uploads/documents`, `uploads/employees`,
   `uploads/organizations` — **755** (если загрузка файлов не работает —
   775/777 временно, затем вернуть, как требует хостинг).

## 4. Проверка после деплоя

1. Откройте `https://<домен>/login.php` — форма входа без ошибок.
2. Войдите `admin` / `admin123` и **сразу смените пароль**
   (Пользователи → admin → пароль).
3. Создайте организацию (с бланком .docx) и сотрудника; загрузите фото и скан
   документа — файлы должны появиться в `uploads/…`.
4. Процесс «Приглашение»: сформируйте Ходатайство, Гарантийное письмо, Опись —
   .docx скачивается и открывается в Word.
5. Отчёты → экспорт Excel; Журнал аудита открывается.
6. Прямые URL должны давать 403/404: `/config/config.php`,
   `/includes/db.php`, `/templates/processes/petition.docx`, а PHP из
   `/uploads/` не выполняется.

Если белый экран/500: включите показ ошибок в панели хостинга или посмотрите
error-log; частые причины — старая версия PHP, нет расширения `zip`/`gd`,
неверные данные в `config/config.php`, не загрузился `vendor/`.

## 5. Безопасность (сделать сразу)

- Смените пароль `admin`; демо-пользователей (`hr_demo` и т.п.) на проде
  не создавайте.
- Пароль БД из `config/config.php` лежит в git-репозитории — считайте его
  скомпрометированным: смените пароль пользователя БД в панели хостинга,
  обновите `config/config.php` на сервере (локальный файл не коммитьте).
- `_deploy_build/` удалите после заливки, не храните копию с паролями.

## Откат

Файлы: залейте предыдущий пакет поверх. БД: phpMyAdmin → Импорт бэкапа,
сделанного на шаге 2 (при rebuild сначала дропаются таблицы — импорт
бэкапа их пересоздаёт).
